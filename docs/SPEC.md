# 仕様書（v1.11.0）

筑波宇宙センター特別公開2026（2026-11-28、10:00〜15:30）の非公式マイスケジュールアプリ。
宇科連70 タイムテーブル（fu-ji-p/ukaren70 v1.5.0）をベースに、事前申込と整理券の管理を加えたものです。

## 1. 構成

## 2. データ（data/program.json）

- `events`: 公式のイベント 58 件。`no`（公式のイベント番号）、題名、エリア、場所と時間の文面、参加方法。
  - `apply`: 事前申込の情報。`method`（lottery/first/tbd）、`start`/`end`（受付開始・締切）、`url`（予約ページ）、`result`（結果通知の案内）、`pending`（申込方法が未発表）、`target`（イベントの一部だけが対象のとき）。
  - `ticket`: 当日整理券の配布時間・場所・枚数。
- `sessions`: 選択の単位。121 件。
  - 時刻の決まった回（78 件）: ID は `イベント番号/回`（例 `14/2`、`45/L1`）。`place` がグリッドの列。
  - 出入り自由の部分（43 件）: ID はイベント番号そのもの（例 `12`）。`open: true`。
  - `needs`: その回に必要な手続き（apply/ticket/first）。
- `places`: グリッドの列になる 16 か所。エリア E → S → C → W の順。

### 公式データに無く、手で補っている項目（`scripts/build_program.py` の `OVERRIDES`）

| 項目 | 補い方 |
|---|---|
| 各回の開始・終了時刻 | 公式の時間の文面（「①10:15～11:15 …」）を読んで入力 |
| 34 すごろくの終了時刻 | 公式は開始時刻のみ。仮に 40 分とし「終了は目安」と表示 |
| 07・08 の終了時刻 | 公式の「各回約15分/約20分」から計算 |
| 23 の時間枠 | 予約ページの記載（10:30〜14:30 の 30 分ごと、計 8 枠）を紹介文に記載。回としては登録せず、出入り自由 + 自分で時刻設定 |
| 45 のラウンジ/ミーティングの時刻 | 公式の紹介文に記載の時刻 |
| 整理券の配布開始時刻（`tickets`） | 公式の配布時間の文面（「10:00～、13:00～」など）から時刻を読んで入力。タイムテーブルの印になる |
| 抽選か先着順か | 公式の注意書きと各イベントの案内から判断 |
| 結果通知の時期 | 公式の「受付終了後の案内」を要約 |
| ひとこと紹介 | 公式の紹介文をもとに自分の言葉で要約 |

## 3. 画面

- **タイムテーブル**: 10:00〜15:30、15 分 = 1 行（内部 5 分単位）。エリアごとに、時刻の決まった回がある場所の列（16 列、幅 96px 以上）と、終日（出入り自由）のイベントを 1 件ずつ入れた細い列（43 列、幅 34px、題名は縦書き）を並べる。同じイベントの回どうしが同じ列で重なる場合（23: 所要 1 時間の回が 30 分ごとに始まる）は、各カードを次の回の開始までの高さで描く（カードの時刻表記は本来の開始–終了のまま）。上段にエリア名。カードの色は参加方法。整理券の配布開始時刻は、整理券が必要な回と同じ列に 🎫 の点線の印（15 分の高さ、配布の終了時刻は不明）で出す。開催日は現在時刻の赤線。申込状況が「落選」のイベントの回は薄く表示する。「当選・予約確定」で、かつ事前申込の回を 1 つ以上追加しているイベントは、追加していない事前申込の回を同じく薄く表示する（当選した回がどれかをアプリは知らないので、追加した回を当選した回とみなす）。「マイスケジュールに追加したイベントのみ」をオンにすると、追加した回とその列だけを表示する（設定は localStorage の `tksc-openday2026.onlyMine` に記憶。マイスケジュール本体とは別のキー）。
- **イベント一覧**: エリア・参加方法・カテゴリで絞り込み。追加済みは ✓。
- **予約・整理券**: 事前申込を「受付中（締切の近い順）→ 受付開始前 → 準備中 → 受付終了」の順に表示。締切 3 日以内は強調し、タブに件数バッジ（自分の状況が未申込のものだけ）。受付中のときだけ予約ページへのリンクを出す（公式サイトと同じ）。 締切が発表済みでまだ過ぎていないイベントには「🔔 締切をリマインド」を出し、そのイベントの締切だけを .ics に書き出す（締切の 24 時間前と 3 時間前の VALARM 付き。予定は締切の 30 分前に始まるので TRIGGER は -PT23H30M と -PT2H30M）。一括書き出しには VALARM を付けない。
- **更新情報**: 毎朝の公式データ確認（定期タスク）で見つけた来場者向けの変更を `data/updates.json`（`[{date, items: [{no?, text}]}]`、新しい日付が先頭）に記録し、上部の「更新情報」ボタンのシートに日付ごとに表示する。イベント番号付きの項目はタップで詳細を開く。まだ開いていない新しい日付があるとボタンに赤い点、シート内では「NEW」を付ける（最後に見た日付は localStorage の `tksc-openday2026.seenUpdates` に記憶。マイスケジュール本体とは別のキー）。
- **最終確認日時**: 定期確認（毎日 8:30・18:30）で `scripts/build_program.py` が公式データの取得に成功するたびに `public/checked.json`（`{"checkedAt": "2026-11-20T08:36:00+09:00"}`）を書き換え、変更がなくてもこのファイルだけコミットして公開する。アプリは実行時に読み込み（キャッシュなし）、「予約・整理券」の案内、⚙ 設定の「このアプリについて」、印刷の末尾に「公式サイトの最終確認 11/20(金) 8:36（内容の最終更新 11/20(金)）」と出す。読めないときは「内容の最終更新」（`program.json` の `generatedAt` = 公式データが最後に変わった日）だけを出す。
- **イベント詳細**: 場所・時間・定員など、申込と整理券の情報、回ごとの ＋/✓ ボタン。出入り自由の部分は「行く時刻（任意）」を設定できる。設定した時刻が開催時間の外（昼休みのある 01・20・33 の休止時間、開催の前後）なら警告を出す（保存はする。終了時刻ちょうども時間外）。
- **マイスケジュール**: 「申込・整理券の確認」「時刻の決まった予定」「いつでも行けるイベント」の 3 部。同じ時間帯は「重複」、エリアが変わるときは「エリア移動」の注記。
- **印刷**: A4 縦。`window.print()`。
- `?now=2026-11-28T10:30` を URL に付けると、時刻を偽装して受付状況や現在時刻線を確認できる。

受付状況は端末の時計で判定する（公式サイトと同じ規則）。`pending` のものは常に「準備中」。

## 4. 保存データ

| 項目 | 内容 |
|---|---|
| キー | `tksc-openday2026.schedule.v1`（公開後は変えない） |
| 値 | `{"selected": ["12", "14/2"], "times": {"12": "11:30"}, "apply": {"14": "won"}, "updatedAt": "ISO 8601"}` |
| 失敗時 | 空の状態で起動する |
| 不明な ID | 捨てずに保持し、画面に出さないだけ |

- `apply` の値は `applied`（申込済）、`won`（当選・予約確定）、`lost`（落選）。未申込はキーなし。
- 共有リンクは `#s=12,14/2&t=12@1130&a=14w,19a` の形で同じ内容を運ぶ。開いた側は帯で「読み込む/無視」を選ぶ。
- 形式を変えるときは新しいキー（`v2`）+ 移行処理 + メジャーバージョンアップ。

## 5. 更新手順

1. 公式の更新を取り込むときは `python3 scripts/build_program.py`。警告を確認し、必要なら `OVERRIDES` を直して再実行。
2. `package.json` の `version` を上げ、`CHANGELOG.md` に書く。
3. `npm test && npm run build`。
4. コミットし、同じ番号の注釈付きタグを付けて push（`git tag -a vX.Y.Z -m "..." && git push origin main --tags`）。

セッション ID は公開後に変えない。時刻だけ変わったら ID は据え置いて時刻だけ直す。
